# 任务管理规范

## 1. 权威来源

- `project.md`：项目目标、当前阶段、关键决策、风险和唯一下一步。
- `Task_Board.md`：任务内容、状态、依赖、验收及 Git 关联的唯一权威来源。
- `plans/`：任务计划和执行过程，不另建平行任务状态表。
- `plans/done.md`：DONE 任务的历史归档；Task_Board.md 保留索引。

## 2. 阶段

默认阶段：需求采集、需求分析、概要设计、详细设计、开发、测试、发布。项目可按实际情况增加阶段，但阶段状态必须由项目负责人确认，不得由任务完成比例自动推断。

## 3. 状态转换

| 当前状态 | 允许的下一状态 |
|---|---|
| TODO | IN_PROGRESS、DEFERRED、CANCELLED |
| IN_PROGRESS | BLOCKED、REVIEW、DEFERRED、CANCELLED |
| BLOCKED | IN_PROGRESS、DEFERRED、CANCELLED |
| REVIEW | DONE、IN_PROGRESS、BLOCKED |
| DEFERRED | TODO、IN_PROGRESS、CANCELLED |
| DONE | 默认终态；重新打开需记录原因并获用户授权 |
| CANCELLED | 默认终态；重新打开需记录原因并获用户授权 |

## 4. 状态历史

`Task_Board.md` 的“状态变更记录”是追加式历史。新任务记录“创建”（原状态 `—`、新状态 `TODO`）；每次状态变化记录“状态变更”、原状态、新状态、日期时间及原因/依据。不得删除、改写历史行。DONE/CANCELLED 重新打开时，新状态只能为 TODO 或 IN_PROGRESS，原因/授权依据必须明确包含用户授权事实。每项有历史的任务必须以唯一的“创建”（原状态 `—`、新状态 `TODO`）事件开头；后续才允许“状态变更”。变更时间必须为有效 ISO 8601 日期时间，且同一任务的时间不得倒退。检查器验证创建事件、时间戳格式与顺序、转换合法性、记录连续性以及最新记录与任务当前状态一致。

升级前已存在但完全没有状态历史的任务视为历史基线，检查器给出 INFO，不强制伪造历史记录；一旦某任务开始记录历史，就必须包含创建事件，不能从中途的状态变更开始。后续发生的状态变化必须追加记录。

## 5. 完成与归档

任务只有在交付物存在、验收标准满足、必要测试/检查有记录、台账状态同步后才能标记 DONE。DONE 必须追加到 `plans/done.md`，包含 Task ID、名称、完成日期和验收结果。代码任务应记录真实 Commit SHA；非代码任务不强制 Commit。里程碑任务应记录真实 Tag，普通任务不强制 Tag。

## 6. Git 关联

- 一个任务可关联多个 Commit；一个 Commit 可服务多个任务。
- 记录完整 SHA；检查时在目标仓库验证对象存在。
- Tag 需在目标仓库真实存在，里程碑可关联多个 DONE 任务。
- 无法验证时标记待核实，不得伪造或推断。
- Agent 不得自动执行 commit、tag、checkout、reset 等改变 Git 状态的操作。

## 7. 依赖

前置任务使用 Task ID，多个依赖逗号分隔。所有前置任务均完成后才可开始依赖任务。依赖必须指向存在的任务，不得自引用或形成循环。

## 8. 维护规则

任务类型填写普通、代码、里程碑或代码,里程碑，以区分 Commit 与 Tag 要求。任务 ID 永久唯一；DONE/CANCELLED 不删除；延期任务保留原因；变更状态时同步更新时间并追加状态历史。项目看板只引用任务 ID，不重复维护任务状态。只读检查发现问题时仅报告，不自动修复。

## 9. 路径安全

安装器与检查器拒绝仓库根目录本身为符号链接/目录联接的情况，也拒绝配置目标路径或 Manifest 托管文件路径经过仓库内部的符号链接/目录联接（Reparse Point）。这是为避免逻辑路径位于仓库内、实际写入位置却逃逸仓库边界。检查只覆盖执行时可见的路径状态；并发替换路径仍属于文件系统级 TOCTOU 风险，应避免在安装/升级期间由其他进程修改目录结构。
