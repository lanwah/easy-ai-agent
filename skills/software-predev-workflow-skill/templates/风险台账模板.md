# 风险台账（Risk Register）

- 项目名称：
- 台账版本：1.0
- 最后更新：
- 权威性：本台账是项目风险识别、评估、应对和状态的唯一权威记录。

## 1. 使用规则

- 风险编号使用 `RISK-001` 起的全局唯一递增编号，废弃编号不得复用。
- 推荐项目实例路径：`docs/00_Project_Management/Risk_Register.md`。已有项目先扫描；未经用户批准不得覆盖、迁移、重命名或删除既有风险记录。
- 风险记录应描述尚未发生但可能影响项目目标的不确定事件；已发生的问题应同时关联问题/缺陷/CR 等记录，不得仅以风险状态代替问题管理。
- 概率和影响采用低/中/高定性等级，并填写判断依据；风险等级由项目结合概率、影响和上下文给出，不得在缺乏依据时自动计算或伪造。
- 每项风险必须记录应对措施、责任人（未知时写“待分配”）、状态、复查日期/触发条件及关联事项。
- 用户接受风险时，必须保留明确的用户接受表达、范围和日期（可靠时）；助手建议不构成风险接受。
- 关闭风险时追加关闭依据；不得删除历史或覆盖状态变化。

## 3. 状态定义

- `OPEN`：已识别，尚未开始应对。
- `MITIGATING`：正在执行规避、缓解或转移措施。
- `ACCEPTED`：用户明确接受剩余风险，必须有批准证据、范围和日期。
- `OCCURRED`：风险事件已发生，必须关联相应问题/缺陷/CR/TASK 并执行后续处理。
- `CLOSED`：风险已消除、失效或经证据确认不再适用，必须记录关闭依据。

## 6. 完整性检查

- [ ] RISK 编号唯一且未复用。
- [ ] 风险描述说明不确定事件、成因和潜在影响。
- [ ] 概率、影响及其判断依据完整。
- [ ] 应对措施、应急/回退措施及责任人/待分配状态明确。
- [ ] 状态属于规定枚举；`ACCEPTED` 有用户明确接受证据。
- [ ] `OCCURRED` 已关联问题/缺陷/CR/TASK 等处置记录。
- [ ] 复查日期/触发点明确；关闭记录有依据。
- [ ] 与 project.md 风险摘要、Task_Board 关联及阶段评审材料一致。
