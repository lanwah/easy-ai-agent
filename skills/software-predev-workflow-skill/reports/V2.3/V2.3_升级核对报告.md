## 3. 核心规则核对

- P1/P2 不创建正式 Demo；P3 在 SRS 获批后引入；P4 在概要设计获批后完善。
- Demo 采用可交互网页原型，保存在 `docs/design-demo/current/`；Demo 不放入 `src/`。
- 不建立 `milestones/` 或 `history/` 目录；Git Commit 记录日常修改，Annotated Tag 记录重要里程碑。
- Tag 是仓库级引用，必须指向包含完整 Demo 快照的 Commit；正式 Tag 建立在稳定集成分支。
- P4 结束时详细设计文档和 Demo 分别评审、分别取得用户明确批准，才可建立正式设计基线。
- 正式基线 Tag 不得随意删除、移动、覆盖或复用；后续修改走 CR 并创建新版本。
- Demo 不替代设计文档，不自动改变需求/设计基线；开发时详细设计为业务/技术权威依据，Demo 为视觉/交互参照。
- V2.2 澄清追踪、阶段门禁、需求基线保护和 CR 规则保留。
