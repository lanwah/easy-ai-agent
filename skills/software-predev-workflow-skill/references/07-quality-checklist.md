# 07 质量检查规范

## 1. 通用检查

- 输入资料和当前基线可识别。
- 原始表达、来源和确认状态可追踪。
- 编号唯一、引用有效、废弃编号未重用。
- 文档标题、版本、状态、日期、台账和基线一致。
- 假设、建议、待验证和用户决定明确区分。
- 未决问题有影响等级、责任/后续动作（未知则标待分配）。
- 变更有原因、影响分析、批准记录和历史版本。

## 2. 需求质量检查

检查完整性、一致性、明确性、可实现性、可测试性、必要性、唯一性和可追踪性。检查正常、异常、边界、权限、恢复、配置、兼容和外部依赖场景。识别重复、冲突、隐含约束、遗漏角色和不可验证描述。

可报告的指标：原始需求登记覆盖率、正式需求来源覆盖率、验收标准覆盖率、冲突数、未决问题数（按等级）、追踪矩阵缺口。分母为零或数据不可用时说明口径或标记 `UNKNOWN`，不制造百分比。

## 3. 设计质量检查

检查需求覆盖、架构边界、模块职责/依赖、接口契约、数据一致性、安全、性能、可靠性、可维护性、部署、可观测性、异常处理和验证计划。未验证的结论必须列出验证方式。

## 4. 阶段门禁检查

确认阶段入口条件满足；交付物完整；阻塞问题为零；非阻塞风险有用户接受记录；评审意见关闭或有条件接受；批准来自用户明确表达；基线版本固定且可追踪。

## 5. 结果格式

每项检查标记 `PASS`、`FAIL`、`BLOCKED`、`UNKNOWN` 或 `N/A`，附证据位置和处理建议。`FAIL`/`BLOCKED` 不得被总体“基本通过”掩盖。提交评审时输出缺口清单和门禁结论。

## 6. 问题澄清全过程质量检查（V2.2）

- [ ] 每个需用户选择/确认的问题均有独立澄清台账记录和稳定编号。
- [ ] 问题原文、背景、影响范围和关联 RAW/Q/ADR 完整。
- [ ] 所有候选选项均保存完整描述，且逐项列出优点、缺点、代价/风险。
- [ ] 助手每轮均给出推荐选项、理由、置信度、依据及未知条件。
- [ ] 用户每次回答、补充、否决、改选均按时间追加保留，未覆盖历史。
- [ ] 未回答选项未被误标为拒绝；部分回答未被误标为全部确认。
- [ ] 暂缓事项记录原因和触发条件；全部否决事项保留原文并重新澄清。
- [ ] 最终选择有明确用户确认表达/依据，且与决策台账一致。
- [ ] 未确认推荐/候选方案未进入正式需求、设计或基线。
- [ ] 跨会话恢复内容与澄清台账历史一致。

任一必填项缺失，相关问题不得标记为已完成；影响当前阶段范围或基线时标记 `BLOCKED`。


## 7. 设计 Demo 质量检查（V2.3）

- [ ] Demo 创建阶段正确：P1/P2 未提前创建正式 Demo；P3/P4 入口批准条件满足。
- [ ] Demo 位于 `docs/design-demo/current/`，未混入 `src/`；目录说明和运行方式齐全。
- [ ] Demo 采用可交互网页原型，当前版本可按说明运行/预览；依赖、浏览器和限制已说明。
- [ ] P3 覆盖整体布局、页面结构、主要视觉方向和核心流程；P4 覆盖控件、状态、反馈、异常和页面联动（按阶段适用）。
- [ ] Demo 中展示的功能与需求/设计可追踪；未展示的后台逻辑未被误判为不需要实现。
- [ ] 与 SRS、概要设计、详细设计的差异已列明；阻塞冲突已解决或阻断基线。
- [ ] 新增功能、需求语义变化和已批准设计变化已走澄清/CR；未确认建议未进入正式基线。
- [ ] `change-log.md` 记录重要修改原因、影响、关联需求/CR/评审和版本。
- [ ] Git Commit 可追踪；重要 Tag 为 Annotated Tag，命名符合 `demo-v*`；Tag 指向完整 Demo Commit。
- [ ] 正式基线 Tag 不可随意移动/删除/覆盖；里程碑 Tag 不被误认为用户批准。
- [ ] P4 正式冻结时，详细设计文档和 Demo 分别评审、分别获用户明确批准。
- [ ] 正式基线记录关联详细设计基线、Demo 版本、Commit 哈希、Tag、评审记录和批准证据。

任一影响需求正确性、设计一致性、完整恢复或批准有效性的检查项失败，正式基线标记 `BLOCKED`，不得通过创建 Tag 绕过门禁。

## 8. 项目看板与任务台账质量检查（V2.4）

- [ ] `project.md` 六个固定章节完整，阶段/任务/决策/风险摘要可追溯，且只有一个可执行下一步。
- [ ] `Task_Board.md` 的 TASK 编号唯一且不复用，必填字段、状态和完成条件齐全。
- [ ] TASK 类型使用统一枚举；`CUSTOM:<名称>` 已在项目扩展类型表登记且定义清楚。
- [ ] 风险台账存在或已明确标记不适用；RISK 编号唯一，风险描述、概率/影响、应对措施、责任人/待分配、状态和关联记录完整。
- [ ] BLOCKED 有原因；DONE 有完成证据并关联 `plans/done.md`；DONE 不留在活跃区。
- [ ] `Project_Status.md` 是阶段状态唯一权威源；看板阶段摘要一致。
- [ ] TASK 对 RAW/Q/ADR/CR/RISK/AC 的引用有效；TASK 不替代专业台账。
- [ ] Git 不可访问时标记 `NOT_CHECKED`，不得推断 PASS。
- [ ] 任务完成、阶段评审、用户批准、基线建立分别记录。
- [ ] 检查为只读，不自动修复或更改状态。

权威状态冲突、重复编号、DONE 无证据或缺归档标记 FAIL；资料不可访问标记 NOT_CHECKED。
